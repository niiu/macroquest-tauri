# Макроквест

## Версия 0.2 — Tauri 2, несколько квестов и атлас

Настольная версия работает в собственном окне Tauri 2 и хранит квесты и общий атлас в SQLite. Браузерная версия остаётся доступна для разработки и использует IndexedDB.

Установка зависимостей: `npm ci`. Браузер: `npm start`. Настольный режим: `npm run desktop`. Windows-установщик: `npm run build:windows`. Проверки: `npm test` и `cargo test --manifest-path src-tauri/Cargo.toml`. Для сборки нужны Node.js, Rust 1.90 (зафиксирован в `rust-toolchain.toml`), Microsoft C++ Build Tools и WebView2. Пользователю собранного приложения Node.js и Rust не нужны.

Сборка выпускает `src-tauri/target/release/macroquest.exe` и `src-tauri/target/release/bundle/nsis/Macroquest_0.2.10_x64-setup.exe`. Ресурсы визуального редактора собираются локально, приложение не зависит от CDN. Конфигурация оболочки соответствует [документации Tauri 2](https://v2.tauri.app/reference/config/). Отдельные сборки 0.2.1–0.2.10, исходники и журналы проверок находятся в `dist/releases/`. Изменения перечислены в [CHANGELOG.md](CHANGELOG.md).

В настольной версии консоль открывается кнопкой «Консоль», F12 или Ctrl+Shift+I.

### Квесты

В боковой панели появился список «Квесты мастерской». «Новый квест», импорт JSON и загрузка демо создают отдельные проекты. Переключение сначала дожидается сохранения. Каждый квест имеет независимые сцены, персонажей и настройки ссылок. Название меняется обычным полем «Название квеста». «Графический режим» сохраняется отдельно в каждом квесте: картинка и персонажи находятся сверху, текст и варианты действий — в двух раскрываемых блоках снизу.

В браузере старый текущий проект автоматически добавляется в новый каталог без удаления исходной записи. У настольного приложения отдельное хранилище: для переноса из версии 0.1 экспортируйте квест в JSON в старом браузере и импортируйте его в новом приложении. JSON квеста по-прежнему использует `version: 1`; версия приложения и версия формата независимы.

### Атлас

Вкладка «Атлас мира» содержит статьи типов «Лор», «Персонаж», «Локация», «Предмет». Корневая индексная категория «Мир» содержит основные категории «Лор», «Локации», «Персонажи», «Предметы». Кнопка «+» рядом с названием создаёт подкатегорию; «Создать статью» находится внутри обычной категории. Индексные категории содержат только подкатегории. В настройках категории можно изменить название и родителя; циклы запрещены. Для удаления категории сначала перенесите её статьи и вложенные категории. Поиск ищет по названию, краткому описанию и тексту.

Старая структура автоматически переносится под «Мир», сохраняя идентификаторы и вложенность. Перед первой миграцией исходный атлас сохраняется в отдельной записи базы `atlas-before-taxonomy-v1` (отдельной кнопки восстановления этой записи пока нет).

Статья содержит название, альтернативные имена, краткое описание для игрока, полный Markdown и до 30 изображений. Встроенный редактор переключается между визуальным режимом и Markdown. Изображения для персонажей и локаций добавляются в блоке «Спрайты / изображения». **Статьи сохраняются кнопкой «Сохранить статью»**; несохранённый черновик сохраняется при переключении вкладок, но не после закрытия приложения. Переход к другой статье предупреждает о несохранённых изменениях.

«Атлас JSON» переносит всю библиотеку с категориями и картинками. «Подключить атлас JSON» заменяет общую библиотеку после подтверждения, не меняя копии в квестах. Markdown можно экспортировать для отдельной статьи или всех статей одним файлом, с путями категорий и встроенными изображениями. JSON предназначен для обратного импорта с сохранением метаданных; импорт Markdown пока не реализован.

### Атлас в квесте

В редакторе сцены выберите статью в блоке «Из атласа мира» и нажмите «Добавить в квест / применить к сцене»:

- Персонаж копируется в библиотеку NPC с именем, кратким описанием и всеми спрайтами. Его можно размещать обычными средствами редактора. Повторное добавление обновляет имя, описание и спрайты без создания дубля. Идентификаторы картинок сохраняются при перестановке в атласе; удалённые из атласа картинки сохраняются в квесте, если используются на сценах.
- Локация задаёт название, краткое описание и фон выбранной сцены. Пустой текст сцены заполняется описанием. Замена существующего фона требует подтверждения и очищает зоны действий; сами действия сохраняются. Статья без изображения убирает прежний фон.
- Лор и предметы добавляются как справочные описания.

Чекбокс «Кликабельные описания в тексте» включает ссылки для этого квеста; по умолчанию выключен. Названия и альтернативные имена добавленных статей распознаются без учёта регистра, по границам слов. Склонения задавайте альтернативными именами. При совпадениях выбирается самое длинное имя; одинаковые имена разных статей разрешаются в пользу первой добавленной статьи. Ссылки доступны в текстовом просмотре редактора сцены, в прохождении, в репликах диалогов и в автономном HTML. В редактируемом textarea текст остаётся обычным.

В квест переносятся независимые копии. Полный текст статьи не включается в HTML, чтобы не раскрывать авторские заметки; игрок видит только краткое описание. Изменения атласа не меняют старые квесты автоматически. Повторное добавление обновляет справочное описание.

### Хранение

На Windows база находится в `%APPDATA%/ru.macroquest.editor/macroquest.sqlite3`. Записи квестов, каталог и атлас разделены; изменение квеста не переписывает остальные квесты. Запись квеста и каталога выполняется одной SQLite-транзакцией. Сохранения квеста объединяются с задержкой 350 мс, при переключении и закрытии настольного окна ожидается завершение записи. Атлас читается один раз при запуске и сохраняется по явной команде. В SQLite включены WAL и `synchronous=FULL`.

Экспорт JSON, HTML и Markdown в настольной версии открывает системный диалог выбора файла. Для резервного копирования используйте экспорты квестов и атласа. При копировании самой SQLite-базы сначала закройте приложение; при открытом приложении рядом могут находиться файлы WAL.

Новые модули: `workspace.js` — библиотека квестов и интерфейс атласа; `atlas.js` — модель атласа и общий движок описаний; `src-tauri/` — оболочка, SQLite и системное сохранение файлов; `prepare-vendor.cjs` и `build-frontend.cjs` — автономная сборка фронтенда. `atlas.test.cjs`, `workspace.test.cjs` и Rust-тесты проверяют иерархию, копирование, миграцию, переключение квестов и атомарность записи.

Ниже описаны исходные возможности редактора. Раздел о старом Windows-launcher относится только к версии 0.1.

Прежний [контракт библиотеки персонажей](docs/character-library.md) сохранён для справки. В версии 0.2 общая библиотека реализована через атлас; квесты содержат независимые копии NPC. Тестовый персонаж с прозрачным фоном: `assets/characters/test-wanderer.png`.

Редактор ветвящихся текстовых квестов. После `npm ci` можно открыть `index.html` в современном браузере; для постоянного адреса хранилища используйте `npm start`.

## Возможности

- Граф сцен с перетаскиванием, масштабом и линиями переходов.
- Ручное расширение поля кнопками по четырём краям (по 1200 единиц). Мини-карта снизу: клик или перетаскивание для перехода, рамка показывает видимую область. Размер поля сохраняется в JSON проекта; новая сцена появляется в текущей видимой области. Перетаскивание сцен не увеличивает поле автоматически. Защитный предел — 100 000 × 100 000 единиц.
- Создание, редактирование и удаление сцен; выбор начала истории.
- Варианты действий с переходами, включая циклы.
- Прохождение квеста в модальном окне.
- Редактор сцены открывается поверх графа по клику на узел. Вкладки: текст, картинка и зоны, действия и условия.
- На экранах до 720 px редактор автоматически находится под графом. На компьютере этот режим можно включить чекбоксом «Редактор под графом»; выбор запоминается в браузере.
- Прокладка путей перетаскиванием из правой точки сцены к другой сцене, либо двумя кликами. Сразу открывается настройка перехода; линия создаётся после сохранения.
- Редактирование пути и его условий по клику на линию или подпись. Стрелки показывают направление, ромб отмечает наличие условий.
- Крестик во входном кружке отключает конкретный путь. У каждого входящего пути свой кружок; во время прокладки крестики скрыты и кружки служат для подключения. «Вернуть путь» восстанавливает последнее отключение вместе с условиями и зоной до перезагрузки страницы.
- Характеристики, предметы и флаги с начальными значениями; условия «все»/«хотя бы одно». Проверка условий в прохождении для кнопок и зон изображения.
- Последствия перехода: прибавить или задать характеристику, выдать/забрать предметы, включить/выключить/переключить флаг. Выполняются при переходе по кнопке или зоне на изображении.
- Изображения локаций (PNG, JPG, WebP): загрузка до 15 МБ, уменьшение до 1600 пикселей по длинной стороне.
- Произвольные зоны действий поверх картинки: кисть, размер кисти, ластик для выбранной зоны, отмена последнего штриха и очистка зоны.
- Переход по клику на зону в режиме прохождения, подсказка при наведении и включаемая подсветка зон. Пути с нарисованными зонами показываются стрелками с названием сцены прямо на изображении, без дублирования внизу; действия без зон остаются текстовыми кнопками.
- Автосохранение текущего проекта в IndexedDB; импорт и экспорт JSON вместе с изображениями и зонами. Старые текстовые проекты из localStorage загружаются автоматически.
- Экспорт готовой игры в один HTML-файл: встроенные картинки, зоны, условия, последствия, просмотр персонажа и инвентаря. Открывается в современном браузере без интернета и сервера.
- Демонстрационный квест при первом запуске.

В браузерном режиме сохранение привязано к браузеру и адресу страницы. Для переноса используйте экспорт JSON. Открытие другого квеста добавляет его в список мастерской.

Для запуска по постоянному локальному адресу с Node.js: `node dev-server.cjs`, затем откройте http://127.0.0.1:4173. Данные этого адреса хранятся отдельно от открытия HTML-файла напрямую.

## Экспорт готового квеста

Нажмите «↓ Готовый квест · HTML» слева. Браузер предложит сохранить файл с названием квеста и расширением `.html`. Передайте этот файл игроку: достаточно открыть его в браузере с включённым JavaScript. Изображения и весь игровой код находятся внутри; дополнительных файлов, зависимостей и сетевых запросов нет. Экспорт работает и при запуске самого редактора через `index.html` без сервера.

В игре доступны кнопки действий, клики по нарисованным зонам, подсветка зон, характеристики, инвентарь и флаги в режиме просмотра. Условия и последствия выполняются тем же движком, что в редакторе. Редактирование параметров персонажа в готовую игру не включается. «Начать сначала» запрашивает подтверждение и сбрасывает состояние, сохраняя записанные сейвы.

Для дальнейшего редактирования проекта сохраняйте также JSON: HTML предназначен для прохождения и не импортируется редактором как проект.

## Сохранения прохождения

В предпросмотре и готовой HTML-игре откройте «Сохранения». Доступны три ручных слота и отдельное автосохранение после каждого успешного перехода. Сейв содержит текущую сцену, характеристики, количество предметов и флаги. Загрузка восстанавливает состояние без повторного применения последствий перехода.

После открытия страницы игра начинается заново; для продолжения выберите нужный слот или «Автосохранение» и нажмите «Загрузить». Перезапуск не стирает слоты; следующий переход обновляет автосохранение.

«↓ Сейв в файл» скачивает текущее прохождение в `.save.json`, а «↑ Загрузить файл» восстанавливает его. Файл можно перенести на другое устройство или между предпросмотром и HTML-версией того же квеста. Слоты предпросмотра и готовой игры хранятся отдельно в браузере и зависят от адреса страницы. Если браузер запрещает локальное хранение, используйте файлы сейвов.

Сейвы привязаны к содержимому квеста: изменение текста, картинок, параметров или переходов создаёт другую версию; перемещение сцен на графе совместимость сохраняет. Повреждённый или несовместимый сейв отклоняется без изменения текущего прохождения. Чтобы добавить сохранения в ранее скачанную игру, экспортируйте HTML заново.

## Рисование зон

1. Выберите сцену в графе и вкладку «Картинка и зоны».
2. Загрузите картинку. Переходы создавайте прямо на графе или во вкладке «Действия и условия».
3. Выберите действие в списке «Зона действия» или кнопкой «Нарисовать зону» на его карточке.
4. Закрасьте нужную область кистью, как в графическом редакторе. Один штрих — одно нажатие и движение указателя. Можно рисовать несколько несвязанных областей для одного действия.
5. При необходимости используйте ластик, отмену последнего штриха или очистку. Ластик не затрагивает другие действия.
6. Нажмите «Пройти квест» и кликните по нарисованной зоне.

При пересечении зон приоритет имеет последнее действие в списке. Клик вне зон ничего не делает. Замена или удаление картинки очищает её зоны после подтверждения, но сохраняет сами действия. Отмена штриха действует на выбранное действие и доступна после перезагрузки; очистка всей зоны отдельно не отменяется.

## Персонажи и порядок сцен

«Персонажи квеста» — общая библиотека NPC для всех сцен текущего проекта. Создайте персонажа один раз и используйте его повторно без загрузки картинки. «+ Картинка» добавляет варианты (до 30 на NPC); выбор в библиотеке задаёт картинку следующего размещения. В разделе «Слои текущей сцены» можно независимо выбрать картинку каждого слоя. Удаление слоя не удаляет NPC из библиотеки. Используемую картинку нельзя удалить, пока она выбрана хотя бы на одной сцене. Все варианты входят в JSON и HTML-экспорт; старые слои автоматически используют основную картинку.

Во вкладке «Картинка и зоны» нажмите «+ Персонаж», загрузите PNG, JPG или WebP и задайте имя. Перетащите карточку из библиотеки на фон либо нажмите «+ На сцену». Персонаж размещается отдельным слоем: можно двигать его при включённом режиме «Перемещать персонажей», менять размер, поднимать на передний план и убирать со сцены. Для прозрачного фона используйте PNG или WebP. Один персонаж может присутствовать на нескольких сценах. Картинки и положения слоёв сохраняются в проекте и входят в HTML-экспорт.

Крестик в верхнем углу карточки графа удаляет сцену вместе с ведущими к ней путями. «Вернуть сцену» отменяет последнее удаление до перезагрузки. Последнюю сцену удалить нельзя. Перетаскивайте сцены в левом списке вверх или вниз: номера в списке и графе обновляются автоматически, связи и начальная сцена сохраняются. Для клавиатуры доступны Alt + ↑/↓. Перемещение карточки по графу меняет её положение; порядок списка задаётся отдельно.

## Кубик D20

Откройте путь и включите «Проверка D20». Выберите сцены для диапазонов: 1–5 (до 25%), 6–10 (до 50%), 11–15 (до 75%), 16–17 (80–85%) и 18–20 (90–100%, критический результат). Укажите отдельную «Сцену провала». **Пустой диапазон означает провал и переход в эту сцену**, следующий заполненный порог не подставляется. Если сценой провала выбрана исходная, игрок остаётся в ней.

Кубик бросается один раз при нажатии на действие или зону; наведение и отрисовка интерфейса не бросают кубик. Сначала проверяется доступность пути. При успехе применяются его последствия; при провале состояние характеристик, предметов и флагов не меняется. Выпавшее число и результат видны в прохождении. На графе показываются выходы диапазонов и провала. Одинаковая логика работает в предпросмотре и готовом HTML.

## Пути и условия

1. В «Параметрах квеста» над графом добавьте характеристики (числа), предметы (неотрицательное целое количество) и флаги (включён/выключен). Задайте начальные значения.
2. Потяните правую точку сцены к сцене назначения. Можно вместо перетаскивания нажать на точку, затем на сцену назначения; Esc отменяет прокладку. В обоих случаях допускаются петли и несколько путей между одними сценами.
3. Укажите текст действия и условия в открывшемся редакторе пути. Параметры можно создать и из этого окна.
4. Для чисел доступны `≥`, `>`, `=`, `≠`, `≤`, `<`; для флагов — равенство или неравенство выбранному состоянию. Например: Сила ≥ 5 И Ключ ≥ 1 И Дверь открыта = включён.
5. Выберите «все условия» (И) или «хотя бы одно» (ИЛИ). Путь без условий доступен всегда. Сохраните путь; «Отмена» не создаёт переход и не изменяет существующий.
6. В прохождении недоступные кнопки заблокированы и сопровождаются объяснением; недоступные зоны также не выполняют переход. При наложении зон заблокированная верхняя зона не пропускает клик на нижнюю.

В предпросмотре раздел «Состояние персонажа · проверка условий» показывает текущее состояние и позволяет временно менять значения для проверки. Начальные значения проекта не меняются; перезапуск прохождения восстанавливает их.

## Последствия перехода

Нажмите на путь в графе и в разделе «При переходе» добавьте последствия. «Новый параметр» позволяет создать характеристику, предмет или флаг прямо из редактора пути. Затем выберите параметр и операцию:

- **Изменить на**: прибавить число к характеристике или количеству предметов. Например, `+2` выдаёт два предмета, `-1` забирает один.
- **Установить**: задать точное число или состояние флага.
- **Переключить**: поменять состояние флага на противоположное.

Сначала проверяются условия по состоянию до перехода, затем последствия выполняются сверху вниз. Изменения применяются вместе: при нехватке предметов или недопустимом результате переход блокируется, частичных изменений нет. Предметы нельзя увести в отрицательное количество. Повторный проход по пути снова выполняет последствия, в том числе при переходе в ту же сцену. Состояние сохраняется между сценами в рамках текущего прохождения. Наведение, показ кнопок и проверка доступности ничего не начисляют.

Параметр нельзя удалить, пока на него ссылаются условия или последствия, включая открытый черновик пути. Переименование параметра сохраняет связи благодаря стабильному идентификатору.

## Структура

- `index.html` — интерфейс редактора и проигрывателя.
- `style.css` — адаптивная тёмная тема.
- `app.js` — модель проекта, редактирование графа, хранение и проигрыватель.
- `image-editor.js` — загрузка изображений, инструменты рисования и взаимодействие с зонами в проигрывателе.
- `graph-editor.js` — сцены и интерактивные пути, перетаскивание соединений, размещение редактора.
- `path-editor.js` — редактор переходов, параметров и тестового состояния персонажа.
- `rules.js` — валидация и вычисление условий; не зависит от DOM.
- `html-export.js` — сборка автономного HTML и интерфейс готовой игры; движки условий и зон встраиваются из общих модулей.
- `zones.js` — общая геометрия штрихов, отрисовка и проверка попадания в зону.
- `storage.js` — хранилище IndexedDB.
- `saves.js` — общие слоты, автосохранение и переносимые сейвы для предпросмотра и HTML-игры.
- `scene-layers.js` — проверка персонажей, отрисовка слоёв и кнопок путей на изображении; общий модуль предпросмотра и HTML.
- `character-editor.js` — библиотека персонажей, загрузка картинок и размещение слоёв.
- `scene-features.test.cjs` — границы D20, провалы, слои, экспорт, удаление и порядок сцен; запуск: `node scene-features.test.cjs`.
- `saves.test.cjs` — проверки снимков состояния, совместимости, слотов, импорта и ошибок хранения; запуск: `node saves.test.cjs`.
- `dev-server.cjs` — локальный сервер без зависимостей.
- `validate.test.cjs` — проверки формата и геометрии зон; запуск: `node validate.test.cjs`.
- `rules.test.cjs` — проверки характеристик, инвентаря, флагов, режимов И/ИЛИ и сброса состояния; запуск: `node rules.test.cjs`.
- `html-export.test.cjs` — автономность HTML, безопасное встраивание текста и работа экспортированного проигрывателя (переходы, последствия, условия, зоны и перезапуск); запуск: `node html-export.test.cjs`.

Формат JSON: `version: 1`, `title`, `start` (идентификатор начальной сцены), `scenes`. Сцена содержит `id`, `title`, `text`, координаты `x`, `y` и `choices: [{text, target}]`. Сцена без действий считается финалом.

Дополнительные поля совместимы со старыми проектами: `scene.image` — встроенная картинка в data URL; `choice.zone` — список штрихов `{mode: "paint" | "erase", radius, points: [[x, y], ...]}`. Координаты нормализованы от 0 до 1; радиус задан как доля меньшей стороны изображения. Это сохраняет форму зоны при изменении размера интерфейса. Импорт ограничен 100 МБ, 500 сценами, 5000 штрихами на действие и 20000 точками в штрихе.

Параметры хранятся в необязательном массиве `variables: [{id, name, type: "stat" | "item" | "flag", initial}]`. Действие дополнительно содержит `conditions: [{variable, op, value}]` и `conditionMode: "all" | "any"`. `op` — одно из `gte`, `gt`, `eq`, `ne`, `lte`, `lt`. Отсутствие этих полей сохраняет поведение старых квестов. Импорт проверяет типы значений и ссылки условий на параметры.

Последствия хранятся в необязательном поле действия `effects: [{variable, op, value}]`. Операции: `add` (числовое изменение), `set` (точное значение), `toggle` (флаг, поле `value` не требуется). Отсутствующий или пустой список ничего не меняет. Импорт проверяет типы, операции и ссылки на параметры. До 100 последствий на путь. Серверного хранения пока нет.

### Диалоги с NPC
В слоях текущей сцены нажмите «+ Диалог» у персонажа. Создаётся узел реплики на графе: текст сцены — слова NPC, действия — ответы игрока. Для следующих реплик включайте «Реплика диалога»; связывайте их обычными путями с условиями, эффектами и D20. Переход к обычной сцене завершает разговор и меняет локацию. «Завершить разговор» возвращает к исходной сцене. Диалог открывается кликом по NPC или клавишей Enter после выбора через Tab. Сохранения фиксируют локацию и полученные эффекты; после загрузки разговор можно начать снова.

### Диалоговые сцены и новый пример
Чекбокс «Диалоговая сцена» переключает редактор на имя собеседника, реплику и ответы. «+ Следующая реплика» создаёт узел и соединяет его ответом; текст ответа можно изменить. При обычном переходе в диалоговую сцену разговор начинается сразу, а сохранения фиксируют текущую реплику. Диалоги NPC по клику остаются отдельным окном. Кнопка «Тестовый квест» загружает demo-quest.json, предварительно сохраняя текущий проект в IndexedDB; «Вернуть проект до демо» восстанавливает эту копию. Пример содержит зону двери, NPC, ветвление, предмет, флаг, условие, D20 и финал.
Резервная копия до первого открытия демо сохраняется при повторной загрузке примера.

Редактор сцены объединяет текст, изображение, персонажей и действия на одной странице. В диалоговом режиме доступны фон и слои NPC; реплика и ответы показываются вместе с иллюстрацией в просмотре и HTML-экспорте.

Картинка и зоны находятся выше ответов в редакторе. Диалоговый режим сохраняет интерактивность изображения: клик по NPC открывает разговор, клик по зоне выполняет соответствующий переход с проверкой условий и эффектами.

«+ Следующая реплика» копирует фон и слои персонажей из текущей реплики. Под кнопкой расположен чекбокс «Новая локация в следующей реплике»: с галочкой новая реплика создаётся без фона и персонажей, без галочки — с их независимыми копиями. Загрузка и замена картинки доступны всегда. Чекбокс применяется только к следующему созданию и затем сбрасывается.

Связи размещённых NPC с диалогами видны на графе голубым пунктиром с именем персонажа. Клик по подписи открывает реплику диалога; крестик у входа отключает разговор у этого слоя, не удаляя персонажа. Отключение можно отменить. Эти связи отражают настройки слоёв и обновляются при их изменении.

Окно разговора с NPC показывает картинку текущей реплики и её слои персонажей над текстом и ответами. При переходе к другой реплике иллюстрация обновляется; реплики без изображения остаются текстовыми. Поддерживается просмотр и автономный HTML.

## Windows 0.1: прежний установщик и portable (архив)

Готовые сборки создаются в dist/: Macroquest-0.1.0-Setup.exe и Macroquest-0.1.0-Portable.zip. Установщик работает для текущего пользователя, добавляет ярлык в меню «Пуск», а ярлык рабочего стола — по выбору. Portable достаточно распаковать и запустить Macroquest.exe. Node.js пользователю не нужен. Требуются Windows 10/11 и встроенный .NET Framework 4.

EXE содержит файлы редактора, запускает сервер только на 127.0.0.1:4173 и открывает браузер по умолчанию. Значок в трее позволяет открыть редактор или остановить сервер. Закрытие вкладки не завершает сервер. Если на этом адресе уже работает Макроквест, открывается существующий экземпляр; чужой занятый порт не подменяется случайным, чтобы сохранить адрес браузерного хранилища.

Проекты остаются в IndexedDB выбранного браузера и профиля. При переходе из встроенного браузера в другой перенесите проект через экспорт/импорт JSON. Удаление программы не очищает браузерные данные. Сборки пока не имеют цифровой подписи издателя.

### Сборка на Windows

Нужен C#-компилятор .NET Framework (обычно входит в Windows) и [Inno Setup 6](https://jrsoftware.org/isdl.php). Сборка не скачивает инструменты автоматически. Команда: powershell -NoProfile -ExecutionPolicy Bypass -File packaging/windows/build.ps1 -InnoCompiler "C:\Program Files (x86)\Inno Setup 6\ISCC.exe". Локальный путь .tmp/inno/compiler/ISCC.exe используется по умолчанию. npm run build:windows запускает этот же скрипт.

Сборка проверяет все встроенные ресурсы через HTTP, затем выпускает установщик, ZIP и SHA256SUMS.txt. npm run test:windows проверяет сервер на отдельном временном порту, включая запрет доступа к посторонним файлам и неподдерживаемых запросов; тестовый процесс останавливается автоматически. dist/ не коммитится. Для проверки установщика использовались временная установка, проверка установленного EXE и штатное удаление.

При перетаскивании выхода сцены на пустое место графа создаются новая сцена и переход к ней, затем открываются условия и последствия перехода. У диалогового узла создаётся следующая реплика с копией оформления. «Отмена» в редакторе перехода отменяет только правки его настроек: уже созданные сцена и путь остаются. Отпускание вне графа, на интерфейсе или Escape ничего не создаёт.
